# Security requirements the no-cost client architecture cannot guarantee

These are retained requirements, not silently waived requirements. **Real SIN collection and retrieval remain disabled.** Independent review cannot turn an impossible property into a demonstrated technical guarantee. If a non-negotiable requirement remains unmet, stay synthetic-only; no paid workaround is authorized.

| Original security property | Spark-only capability | Gap / release consequence |
| --- | --- | --- |
| Guaranteed one-time reveal/decryption | Rules can restrict exact-document reads and enforce one-way status transitions | Reads do not consume authorization. Clients can retain ciphertext and decrypt repeatedly with a private key. **Not met; real retrieval blocked** |
| Valid SIN and correct encryption enforced server-side | UI validates format/Luhn; Rules check payload schema/type/size and identity | Rules cannot decrypt, verify checksum or prove ciphertext was encrypted correctly. Malicious clients can write garbage or encode plaintext into allowed bytes. **Not met; no guarantee that all accepted writes are valid encrypted SINs** |
| Recent MFA for every reveal | Recent password login can be checked using signed auth_time; TOTP may be available after verified Identity Platform configuration | Password reauthentication is not MFA. Actual project/plan/second-factor enforcement/freshness are unverified; no-billing availability must be proven. **Not demonstrated; deny real ciphertext reads** |
| Guaranteed deletion on deadline without staff online | Request-time Rules reject expired access; staff can manually delete exact payload with tombstone/event | No free Firestore TTL or trusted scheduled backend. Retention deletion can be late during outage/absence. **Not met; deadline denial is not erasure** |
| Per-record managed non-exportable keys and retirement | Offline private keys and public-key rotation | No managed KMS in this design; copied key/ciphertext cannot be revoked, shared key cannot erase an individual retained record. **Not equivalent to original key design** |
| Complete immutable audit of every read/reveal | Append-only validated state-change events, subject to deployed Rules | Rules cannot emit an event on read. Privileged project users bypass Rules; decrypting offline is invisible. **Not met** |
| Strong session cookie isolation and short central idle expiry | Firebase memory-only bearer tokens, auth_time checks, UI sign-out | Tokens accessible to JavaScript; copied refresh token/session can outlive UI idle timer within provider behavior. No HttpOnly server-session backend. **Changed architecture; not equivalent** |
| Strong centralized rate limiting / abuse detection | Provider throttles, per-invitation write constraints, optional approved no-cost App Check | Cannot reliably enforce global IP/mail/read quotas with client code and Rules alone; abuse can exhaust shared Spark quotas. **Partial only** |
| Strong multi-app isolation | Dedicated Hosting site, namespaced documents, role-by-UID checks | Same project shares Auth/IAM/Rules/quotas. Broad existing allow rules or server credentials can defeat isolation. **Unknown until inspection; not a hard isolation boundary** |
| Guaranteed disposal of all copies, including backups | Delete active payload, retain consumption tombstone, procedural key handling | No application can revoke prior browser/operator copies; provider residual copies follow provider terms. Spark managed backup/PITR unavailable. **No immediate/global erasure claim** |
| Production rejects arbitrary real data during testing | Current static prototype has no input/network writes; emulator-only tests use fixtures | Once real-project direct encrypted writes are enabled, Rules cannot tell synthetic from real hidden content. **Do not enable live payload writes for a synthetic-only prototype** |
| Safe local private-key import while maintaining original no-export flow | Offline isolated utility can be designed with verified artifact and transient key | Ciphertext handoff and approved existing custody resources are unresolved; no added CSV/download feature. **Local decryption is not implemented/approved** |

Properties likely enforceable with correct, tested Rules include verified-email + active-invitation authorization, exact own invitation lookup, create-once deterministic submission slots, contractor read/update denial, separate roles, exact assigned-custodian get (repeatable), paired active deletion/status updates, no broad payload list and future-read expiry. They are proposals until emulator and actual-project regression tests pass. Project IAM administrators remain outside these client-rule guarantees.

No claim of compliance, issued-SIN identity verification, screenshot prevention, exactly-once human observation, perfect browser memory erasure or production readiness. The approved financial ceiling stays CAD $0 even when a requirement cannot be met.
