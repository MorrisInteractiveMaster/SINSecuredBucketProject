## Security and operational limits

- Actual OAuth sign-in, Microsoft ID-token/member claim delivery, App Check attestation and inherited cloud IAM cannot be proven with local mock assertions. The cloud runtime tests use signed Auth-emulator sessions and deliberately injected Microsoft verification fixtures; real provider acceptance remains an owner smoke test.
- App Check is explicitly verified with Firebase Admin SDK by this endpoint only, with exact portal App ID. The cloud entry implements the published non-streaming JSON callable protocol over an HTTPS Function so malformed request bodies are rejected before Firebase callable middleware can log them; the existing `httpsCallable` client is retained. Token/SDK exceptions become fixed errors, without raw error/stack/body logging. Unit tests verify malformed envelopes, attestation/error handling and actual Firebase client success/error interoperability using a deliberately mocked attestation verifier. Platform ingress/body-parser/access logging still needs live review before production; no web server can stop a hostile caller from placing personal data in an arbitrary URL. Do not enable enforcement for shared Auth/Firestore products. reCAPTCHA adds device/risk processing and CSP origins; `style-src 'unsafe-inline'` is retained for its widget styling, while scripts are restricted to self and specific reCAPTCHA origins. Inspect real browser CSP/errors before sharing. CSP is not proof that browser extensions or compromised frontend code cannot read input.
- Hosting previews share cloud resources, are publicly reachable URLs and require exact-domain Auth/reCAPTCHA approval before OAuth testing. No Google/Microsoft account linking is automatically performed by portal code; test Firebase's actual shared account policy and conflicts safely.
- Retention timestamps are not automatic deletion. The test key is discarded, no recovery/decryption service exists, and real transfer/disposal remains disabled. Rollback cannot recall previously delivered metadata or instantly erase provider backup copies.
- New portal Auth users may be visible to the existing app. Existing app authorization must reject unintended users, and its sign-in/data flows must be regression-tested without changing its configuration here.
